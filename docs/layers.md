# v0.5.0：透明主体与独立运动

现有 cinematic 模式可在每幕增加 `layers`，最多4层。仍从 Skill 的 init / validate / patch / render / verify 入口执行，无独立试片渲染器。

```json
{
  "layers": [{
    "id":"plane", "asset":"assets/plane.png", "width":0.29,
    "path":[[0.22,0.59],[0.40,0.43],[0.61,0.58],[0.79,0.45]],
    "rotation":2.2, "bob":0.008, "period":3.2
  }]
}
```

- 主体必须为真正有透明像素、也有可见像素的 PNG。校验使用 FFmpeg 实际读取 Alpha，不能只按文件名或RGBA格式猜测透明。
- 原图可保留整幅透明画布。渲染时自动测量 Alpha 包围框，并在滤镜中取出主体；不修改原文件。
- width 为主体可见宽度相对于输出画布宽度的比例，0..1。path 为三次贝塞尔曲线的四个控制点，坐标归一化到画面宽高，描述主体中心的位置。
- rotation 为正弦摆动的最大角度，最多15度。bob 为上下起伏相对画面高度的幅度，最多0.05；period 为周期秒数，0.5..10。当前没有动态缩放或三维翻转。
- 图层按数组顺序叠放在背景相机画面上。背景与主体运动独立；不是自动三维重建，不处理与背景物体的真实遮挡。
- 自然语言“往右飞远一点”由宿主 Agent 修改目标层 path，再用 scene patch 写回 layers 数组。稳定层id用于定位，Agent 必须保留其他层参数。
- 原分镜缓存键同时包含所有主体文件的内容哈希与运动参数。主体图文件变化会令旧QA失效；改某层会重渲染所属幕，未改的其他幕继续复用。
- 新增图层会参与转场和最终音轨合成，组合能力沿用 v0.4.0。

本次输入：用户提供的无飞机背景1672×941 RGB，透明主体1672×941 RGBA，可见Alpha包围框为x=517、y=387、宽523、高217；自动检测到透明像素与可见像素。界面上显示的隐含RGB背景不代表Alpha无效。

六秒试片验证了分层运动与实际路径修改。它不等于整支MV已升级，列车和城市图层尚未提供。当前 v0.5.0 在 Windows 本机验证，未在 CodeArts 回归。

运行时不需要 Pillow 或 NumPy，依赖仍为 Node、FFmpeg/ffprobe 和系统字体。图片编辑/抠图由用户外部生成工具提供，本 Skill 只校验和渲染现成图层，不自动保证抠图质量。
